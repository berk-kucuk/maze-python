# PIP-ONLY LIBRARIES ARE PINNED to exact versions (the ones maze-python
# 1.1.0-1 shipped). Unpinned, every package build pulled whatever PyPI served
# that minute, unverified, straight into a runtime six apps execute — and two of
# these (galeodes, social-analyzer) are small single-maintainer projects, the
# classic target of a hijacked-release attack. Bump a pin deliberately, after
# reading the upstream changelog, and rebuild.
# maze-python — the ONE Python environment every Maze desktop app runs in
# (/opt/maze/venv). This is the union of what the apps need; the app that
# needs each line is named so a dependency can be dropped when its app goes.
#
# HOW THIS FILE IS USED. The venv is created with --system-site-packages, so
# a library is taken from the Arch repository whenever one exists (it is then a
# pacman `depends=` entry in PKGBUILD and the user's machine fetches it from an
# Arch mirror — fast, deduplicated with the rest of the system, and never
# uploaded to the Maze repo). ONLY the lines in the "pip-only" block at the
# bottom are installed into the venv itself, with --no-deps, because they have
# no Arch package; their dependencies are Arch packages too and are listed in
# PKGBUILD. Keep the two files in sync: a new library goes to depends= if
# `pacman -Si python-<name>` finds it, to the pip-only block otherwise.
#
# Resolved together on 2026-09-22.
